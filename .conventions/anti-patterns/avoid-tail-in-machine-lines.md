# Хвост в строках, которые читает машина

Строку значения копируют дальше целиком или разбирают регуляркой — пояснение в той же строке
ломает потребителя.

- `Plugin root: <abs> (способ 1)` в state.md (ревью задачи 8): значение уходит в `PLUGIN:` всех
  ролей и в `test -x <Plugin root>/scripts/supervisor-tick.py` — с хвостом путь неверен везде.
- `task: #3` в шапке письма: до 0.18.1 `team-wait.sh` его принимал, а `read_mail` тика искал
  задачу `#3` в PLAN.md, не находил, и `accept_needed` будил вечно; `task: 3 (rework)` давал
  TIMEOUT у team-wait. С 0.18.1 оба читателя берут id через `task_id` (первое слово без одного
  ведущего `#`): `#3` и `3 (rework)` — задача 3, `33` и `3x` — нет.
- `Kind: DONE` с заглавной: до 0.18.1 тик (`read_mail`, чувствителен к регистру) письма не видел,
  team-wait видел. С 0.18.1 ключ шапки оба читают без учёта регистра и пробелов по краям. Как
  раньше: лишний ключ (`to:`) обрывает разбор шапки у тика.

Плохо:

```text
Plugin root: /home/u/.claude/plugins/cache/supertick/supertick/0.18.0 (способ 1)
from: coder-3
Kind: DONE
task: #3
```

Хорошо:

```text
Plugin root: /home/u/.claude/plugins/cache/supertick/supertick/0.18.0
from: coder-3
kind: DONE
task: 3
ts: 2026-10-21T21:40:00+03:00
```

Почему: письмо пишет `team-mail.sh` — он даёт канон сам; роль без Bash повторяет его Write'ом
ровно. Пояснения (номер способа и т. п.) — в ленту или отдельной строкой. Терпимость читателей с
0.18.1 (прогон feature-trial-medium, 22.10.2026) — страховка, а не разрешение: канон записи
прежний и обязателен — строчные ключи, голый id, в отчёте приёмки `ACCEPT:` одна и первая.
Остальные потребители (`Plugin root:`, заголовки PLAN.md у `plan_tasks`) хвост не прощают.
