# Чистая комната: как писались тексты supertick и чем это проверено

У исходного плагина agent-teams нет лицензии, поэтому его тексты в supertick не переносились
ни дословно, ни близким пересказом. Здесь описано, как была устроена работа и какие числа дала
сверка с исходником.

## Как делали

- **Две стороны.** Спецификацию писали два исполнителя «грязной» стороны: только они читали
  исходные файлы. В спецификацию попадали факты (шаги, файлы, сигналы, форматы сообщений, пороги,
  числа, ловушки), изложенные короткими пунктами. Цитаты длиннее шести слов не допускались, кроме
  имён интерфейса.
- **Писатели не видели исходник.** Роли, навыки, справки и README писали исполнители «чистой»
  стороны. Источников у них было три: спецификация, наши скрипты и пример конфига. Открывать
  файлы исходного плагина им было запрещено. Чтобы авторский текст не попал к ним через системный
  промпт, писатели и рецензент запускались нейтральным типом агента, а инструкцию к работе для них
  ведущий написал сам.
- **Наш код.** Семь скриптов, их тест и справка супервизора — наш код линии 0.14–0.17. В 0.18.0
  они перенесены побайтно и в сверке исключены из корпуса. В 0.18.1 три из них изменены:
  `scripts/supervisor-tick.py`, `scripts/team-wait.sh` и `references/supervisor.md`. Остальные
  шесть по-прежнему побайтные, а из корпуса сверки исключены все девять: это наш код.
  Что изменилось в 0.18.1:
  - ключи шапки письма (`from:`, `kind:`, `task:`, `ts:`) тик и `team-wait.sh` читают без учёта
    регистра, пробелы вокруг ключа и значения и `\r` снимаются, ключ повторён — побеждает
    последний;
  - id задачи в `task:` — первое слово значения без одного ведущего `#`: `#3` и `3 (rework)` —
    задача 3, `33` — нет; регистр id сохраняется (`2A` ≠ `2a`);
  - граница шапки осталась разной, как в 0.18.0: тик кончает шапку на первой строке без одного из
    четырёх ключей (`to:`, строка без `:`, строка из пробелов), `team-wait.sh` читает до первой
    пустой строки; `team-mail.sh` таких строк не пишет;
  - вердикт приёмки тик берёт только из первой непустой строки отчёта;
  - `references/supervisor.md` описывает эти правила.
  Причина — расхождения, найденные в прогоне feature-supertick: тик не видел `Kind: STUCK`, а
  `team-wait.sh` видел; письмо с `task: 3 (rework)` ожидание не узнавало; строка
  `ACCEPT: … PASS` в любом месте отчёта давала PASS. Канон записи не изменился: `team-mail.sh`
  пишет строчные ключи и голый id, `ACCEPT:` в отчёте одна и первая.
  Что изменилось в 0.19.0 (меняются те же три файла, остальные шесть по-прежнему побайтные):
  - `scripts/supervisor-tick.py`: порог `engine_result_unread` зависит от того, кто ждёт ответ.
    У участника-прокси (есть карточка `runs/<имя>.json`, статус не `stopped` и не `done`) P0
    поднимается через 3 минуты после `.done`, пока карточка не новее маркера; прокси снимает
    сигнал строкой `note="ENGINE READ"`. У разовой роли ведущего порог прежний, 15 минут;
  - `scripts/team-wait.sh`: правлены только комментарии шапки (ожидание в переднем плане);
  - `references/supervisor.md` описывает новый порог;
  - новый тест `tools/tests/test_tick_proxy_unread.py` (8 случаев) грузит тик из файла и
    проверяет оба порога. Тест супервизора в `scripts/tests` не тронут.
  Причина — испытательные прогоны feature-trial-simple и feature-trial-medium: прокси не
  перечитывал готовый ответ движка, а тик молчал 15 минут.
- **Один реестр протокола.** Токены сообщений, команды ведущего, шапки писем и форматы файлов
  записаны в одном месте. Из него собран белый список сверки.

## Сверка

Инструмент: `tools/overlap_check.py`. Корпус — каталог `plugins/agent-teams` форка на коммите
`ffc350e5abb5c5bb299ac93ce218a49992ed4480`, 24 файла (наши девять исключены через `--exclude`). Цели:
`plugins/supertick`, `tools/`, `README.md`, `README.ru.md`, `docs/measurements.md`, всего 47 файлов
(в задаче 12 их было 41: скрипты сверки `tools/build_whitelist.py`, `tools/run_overlap.sh`,
`tools/token_check.py` и их тест появились в `tools/` позже; с прошлого отчёта добавились тесты
`tools/tests/test_run_overlap.py` и, в 0.19.0, `tools/tests/test_tick_proxy_unread.py`). Полный отчёт: `docs/overlap-report.json`
— последний прогон, после межзадачных правок; таблица ниже — прогон задачи 12.
В отчёт записывается SHA из git HEAD клона корпуса.

### Как повторить

Нужны git-клон исходного репозитория на коммите `ffc350e` и этот репозиторий. Из корня supertick:

    tools/run_overlap.sh --corpus <git-клон исходника на ffc350e>/plugins/agent-teams --json docs/overlap-report.json

Скрипт сам исключает наши девять файлов (`--exclude`), берёт `tools/overlap-whitelist.txt` и
передаёт остальные аргументы в `tools/overlap_check.py`. Без `--corpus` он выходит с кодом 2.
SHA корпуса скрипт берёт из git HEAD клона. Корпус без git (распакованный архив) — добавить
`--corpus-sha <sha>`; `--corpus-sha`, расходящийся с HEAD, — код 2.
Белый список пересобирается из спецификации прогона, которая в репозиторий не входит:
`python3 tools/build_whitelist.py --spec-dir <каталог spec>` (ручной раздел файла сохраняется).

Каналы:
- общие 8-граммы слов: Unicode, NFKC, нижний регистр, без разметки; гасится только 8-грамма,
  все восемь слов которой есть в белом списке;
- дословные строки от 40 символов;
- порядок заголовков `##`;
- окна из пяти «якорей» (пути, имена файлов, SHA, id, числа) в том же порядке. Этот канал
  ловит перевод, но код выхода не меняет.

Белый список `tools/overlap-whitelist.txt`: 521 сгенерированная строка и 9 ручных групп, у каждой
пояснение. Сгенерированная часть содержит все вставки кода из реестра протокола, реестр ролей,
команды пресетов движков и строки frontmatter агентов (`model`, `color`, `tools`). Ручная часть —
интерфейс наших скриптов и Claude Code: ожидание маркера `.done`, справка `engine-sessions.py`,
имя теста, `run_in_background`, команда цикла, статусы плана, имена разделов
`VERIFICATION_PLAN.md`, имена файлов прогона.

| Канал | без белого списка | с белым списком, до правок | после правок |
|---|---|---|---|
| 8-граммы вне белого списка | 407 | 167 | **0** |
| строки ≥ 40 | 3 | 3 | **0** |
| порядок `##` | 0 | 0 | 0 (см. ниже) |
| окна якорей | 14 | 14 | 10, все обоснованы |

Погашено белым списком: 545 общих 8-грамм в задаче 12, 524 в последнем прогоне (1.0.0). Все они целиком состоят из имён интерфейса.

### Что переписано и что обосновано

- `references/engines.md`, **обосновано: факты**. Таблица ролей (id ролей, движки, этап) и
  список проверенных версий CLI — факты, а не формулировки: столбцы и порядок версий
  переставлены, но содержание то же. Цикл сборки диффа новых файлов — команда git (`-o`, своя
  переменная). **Переписано:** пример меток (`004` → `005`, `r2` → `r2-2`).
- `references/phase1-planning.md`: строка статусов в шаблоне плана теперь по-русски («Статусы:»).
  Строки `## Team Name` и `## Complexity` в шаблоне state.md поменялись местами (тик разбирает
  только `## Phase:`).
- `README.md`: заново написаны фразы о воротах задачи, о закрытии задачи по `Status:` и о том,
  почему `acceptance-checker` всегда работает на Claude. `plugins/supertick/README.md`: фраза о
  запуске тестов.
- Попутно закрыты MINOR 2 и 5 ревью задачи 11. Цена пересылки ссылается на
  `docs/measurements.md` вместо номера карточки. Диапазон сборок Claude Code ссылается на
  `team-runtime.md`.

### Окна якорей, которые остались (10), и почему

- `scripts/supervisor-tick.py:56`, `scripts/tests/test_supervisor_tick.py:394`,
  `references/supervisor.md:68` (7 окон): время из нашего же разбора 121-393 (`12:06+03:00` при
  реальных `13:48+02:00`). Эти три файла наши. Тест перенесён побайтно; `supervisor-tick.py` и
  `supervisor.md` изменены в 0.18.1 и 0.19.0, но строки окна остались прежними (в `supervisor.md`
  она сдвинулась с 60 на 68). В корпусе окно составляют те же числа. **Обосновано:** факт-замер.
- `references/engines.md:493–494` (3 окна): каталоги, где codex, kimi, grok и cursor хранят
  сессии (`~/.codex/sessions/…`, `session_index.jsonl`, `~/.cursor/chats`, `meta.json`). Это
  интерфейс внешних CLI, его читает наш `engine-sessions.py`. **Обосновано:** интерфейс.

Необъяснённых окон: 0.

### Порядок разделов

Канал `##` сравнивает текст заголовков, поэтому русские заголовки не совпадут с английскими
никогда, и ноль здесь ничего не доказывает (решение L5). Порядок разделов в пяти файлах
(`agents/coder.md`, `agents/unified-reviewer.md`, `agents/proxy-teammate.md`,
`skills/team-feature/SKILL.md`, `references/phase2-monitoring.md`) выборочно проверяет отдельный
проверяющий, который читает исходник. Он ставит каждому файлу вердикт: «факты в своей структуре»
или «перевод».

### Для справки: 6-граммы

С `--n 6` находится 23 общих фрагмента. Это пути (`plugins/supertick/skills/…`), команды
`git diff --no-index`, строка `allowed-tools` и несколько коротких фраз README. В ворота
этот прогон не входит, цифра приведена для честности.

## Другие проверки этой задачи

- **Токены протокола.** Скрипт `tools/token_check.py --spec-dir <каталог spec>` прошёл
  87 проверок и не нашёл ни одного расхождения. Для каждого токена из реестра голова (например,
  `VERDICT: task #`) есть у отправителя и у получателя. Искажённых написаний (без двоеточия,
  `task` без `#`, другой регистр) нет. Каждый KIND в `team-mail.sh` и `kind:` входит в
  канонический список, а каждый `--kind` у `team-wait.sh` кто-то отправляет. Три подложенные порчи
  (`VERDICT task #` без двоеточия, `IN-REVIEW:`, `--kind VERDIKT`) скрипт нашёл все. Для полноты получатель `NOT A REVIEWER` (кодер) получил в `coder.md`
  одну строку о том, что делать с таким ответом.
- **Проверочная установка** в отдельном `CLAUDE_CONFIG_DIR`. Команды
  `claude plugin marketplace add /var/www/supertick` и `claude plugin install supertick@supertick`
  прошли успешно, версия 0.18.0. У всех семи скриптов в установленной копии стоит бит x. Тик по
  пустому каталогу печатает `P4 ok` и выходит с кодом 0. Время изменения боевых
  `~/.claude/agent-teams.json` и `~/.claude/plugins/installed_plugins.json` осталось прежним.
